# 子插件安装

## 基本信息

- 日期：2026-08-03
- 状态：已完成
- 需求类型：插件安装能力
- 优先级：高
- 需求文件：`aiDoc/memory/business/done/plugin-sub-plugin-installation.md`

## 用户意图

允许将标准插件压缩包安装为已存在插件的子插件。后端和前端资源都必须放在父插件的 `subPlugin` 目录下。应用启动时由父插件注册并启动子插件。子插件菜单的组件路径必须包含父插件路径，确保前端能够找到页面。

## 范围

- 后端：插件压缩包安装、父插件带动子插件启动、子插件 Go import 路径迁移、菜单组件路径迁移。
- 前端源码：文件复制到父插件目录前，迁移子插件内部 import 别名。
- 前端页面：顶部保留顶级插件安装入口，并从对应父插件行发起子插件安装。
- 文档：维护本需求记录和需求索引。
- 涉及模块：系统自动代码插件安装与初始化流程。

## 已确认约束

- 保持原有顶级插件安装流程可用。
- 子插件安装到 `server/plugin/<parent>/subPlugin/<child>` 与 `web/src/plugin/<parent>/subPlugin/<child>`。
- 子插件不得作为顶级 v2 插件自行注册；由父插件调用其 `Register` 方法。
- 初始化前，子插件菜单组件路径由 `plugin/<child>/...` 改为 `plugin/<parent>/subPlugin/<child>/...`。
- 旧版压缩包中已包含嵌套组件前缀时，不得再次添加父插件路径。
- 安装时将子插件前端别名 `@/plugin/<child>/...` 改为 `@/plugin/<parent>/subPlugin/<child>/...`；名称相近的插件别名和已嵌套的别名保持不变。
- 不修改全局插件注册机制，只调整已安装子插件源码和父插件的 `Register` 方法。
